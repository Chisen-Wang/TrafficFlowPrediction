# 数据来源与协议

## PEMS04 / PEMS07 / PEMS08

下载工具使用原项目采用的 [ASTGNN 数据镜像](https://github.com/guoshnBJTU/ASTGNN/tree/main/data)。
镜像使用 `main` 分支，可能变化；每次下载记录实际文件的 SHA-256，复现实验时应保存该清单。
清单是本次下载的记录，不是来自发布者的预先可信校验和。

NPZ 必须包含 `data` 数组，形状分别为 `[T,307,3]`、`[T,883,1]`、`[T,170,3]`。
第一个通道为预测目标。CSV 的边包含起点、终点、距离，准备脚本建立对称高斯加权图并添加自环。
数据不随仓库分发，原始数据的获取和使用条件以各数据发布方为准。

主输入包含流量、日内比例、星期索引，默认一天 288 步。
PEMS 第一天固定视为星期索引 0，是相对日历约定，并非核实后的真实星期。
PEMS04/08 的历史协变量取另外两个原始通道；PEMS07 使用四维日历编码。
已知未来协变量均为四维日历编码；静态变量包含节点索引和图的度统计。

先构建所有滑动窗口，再划分连续的 60% 训练窗口及约 20% 验证、20% 测试窗口。
因此边界窗口会共享部分原始时间戳；该协议为沿用原实现，不是时间戳完全隔离的划分。
少样本比例作用于训练窗口；固定随机种子产生嵌套子集，验证与测试保持完整。
流量和协变量的拟合统计仅来自相应训练部分；少样本模式禁止复用全训练 UniCA 协变量。

## NYC-Bike

数据来自 [STContext](https://github.com/Liyue-Chen/STContext)，下载器固定 commit
`30615d4ffcf804cb1d8e5399ba64e2d1385b668b`。
`download_manifest.json` 保存 URL、文件大小和 SHA-256，准备时核对流量压缩包哈希。
原始流量以包内 `TimeFitness` 为准；小时聚合采用求和，已有小时数据不再重复聚合。
站点顺序按原始 `StationInfo` 行对应流量列，不能排序 ID 后直接配列。

默认 `--cohort first_day` 使用首日已有活动记录的站点，不根据测试期流量筛站。
`first_seen` 表示首次记录活动的时刻，不是经过独立核实的开站日期。
预测目标称为“官方站点流量计数”，不宣称其为双通道借还量。

默认训练目标早于 2016-01-01，验证目标位于 2016 年，测试目标自 2017-01-01 开始。
每个预测窗口的目标必须完全处于所属区间。验证和测试可以使用边界之前已观测到的历史。
不同 split 目标时间不相交，split 内滑动窗口允许重叠。

历史上下文包含七个天气字段，缺失值和有效 mask 分开处理。
未来上下文仅包含小时/星期正余弦及节假日，不使用缺少发布时刻证据的天气预报。
静态变量包括经纬度和 2013 年 POI 八类计数，按站点 500 米内匹配。
物理图为对称 8 近邻图，不使用未来流量或全时段交互统计。
POI 快照的精确发布日期没有核实；将其视为固定空间属性是本项目约定。

默认天气时钟为 `source_naive`，沿用无时区字符串匹配。
原始流量缺少时区/DST 标记，因此不宣称绝对时区已经证实一致。
可用 `--weather-clock gmt_to_new_york` 在独立输出目录进行敏感性实验。
完整上下文审计包含预报、AQI、人口和路网；它们不全部进入模型。

这里只提供协议和验证工具，没有附带旧机器的审计结果，也没有声明重新完成全量数据审计。
